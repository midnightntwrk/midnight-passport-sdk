# E04.02 KeyProvider across p256, k256 and JubJub

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 6  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** core  
**Readiness:** ready · **Sheet title:** Key providers

## Description

One signing interface for every key the account contract (ACC) can verify. Each arm builds the exact digest its circuit checks, from the circuit arguments. This story delivers the digest builders and software key providers for tests. The passkey provider itself is E04.11 (passkey as the first owner key).

The roles are: p256 through WebAuthn is the device arm and the only arm an account is born with. k256 and JubJub stay as schemes for backup keys and grant keys, on arms added later.

In scope: The `KeyProvider` implementation side of the seam from E03.03 (seam interfaces): scheme, optional envelope, `publicKey()`, `sign(challenge)`. A digest builder per arm, taking the circuit name, its arguments, the account address and the current `auth_nonce`. For p256: the WebAuthn challenge and the checks on the assertion profile the circuit accepts (client data length for the compiled origin length, 37-byte authenticator data, ES256). Software providers for p256, k256 envelope 0 and JubJub, for tests and for grant keys. Test vectors per arm, generated from the contract's own pure circuits.

Out of scope: k256 envelope 1 (the wallet connector's `signData` form) as an owner key. Whether the SDK ever enrols one is a contract-side decision for the contract owner. The WebAuthn ceremony, which is E04.11 (passkey as the first owner key). Per-origin and agent grant keys, which are E11 (grant ceremony clients).

## Acceptance criteria

- Each digest builder matches the contract's pure circuit on at least 20 vectors per arm, including the highest and lowest field values.
- A signature made for one account is refused by the verifier for another account with the same nonce (test with the pure circuits).
- A stale `auth_nonce` gives a typed error that tells the caller to re-read state and sign again.
- The p256 builder refuses an assertion outside the accepted profile before any proof is requested, with a typed error.
- The vectors are checked in and regenerate from the pinned artifact with one command.
