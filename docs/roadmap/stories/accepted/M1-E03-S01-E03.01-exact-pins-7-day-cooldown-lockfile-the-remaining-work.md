## Description

Most of this story already exists in the repo: exact pins, the 7-day cooldown job, the lockfile, and the `Cooldown-override:` line in the PR body. What is left is to pin the Midnight stack the SDK builds on, make CI fail when two copies of a Midnight package are installed, and test the cooldown exception.

Board title: Exact pins, 7-day cooldown, lockfile.

In scope: A pin table in `docs/compatibility.md`: Compact 0.36.0, compact-runtime 0.21.0, midnight-js 5.0.0, compact-js and platform-js 3.0.0, proof server 9.0.1, Effect 4 (exact version, bundled, see E03.10 (Effect 4 inside the SDK)). ledger-v9 at 1.0.1 through one override. midnight-js 5.0.0 pins 1.0.0, and 1.0.0 prices some calls lower than the node does, so the node refuses them with error 138. A CI check that ledger-v9, compact-js, compact-runtime and Effect 3 each resolve to one version. A test that a version younger than 7 days fails without `Cooldown-override:` and passes with it, and that the reason is recorded.

Out of scope: the release pipeline, which is E03.07 (signed npm release). Renovate rules beyond what exists.

## Acceptance criteria

- `docs/compatibility.md` lists each pin with its version, and the lockfile matches it.
- `pnpm why` shows one copy each of ledger-v9, compact-js and compact-runtime; a fixture with two copies fails CI.
- The ledger-v9 override is one line, with a comment that says when it can go (midnight-js 5.0.1).
- A fixture dependency younger than 7 days fails the cooldown job; the same fixture with `Cooldown-override: <reason>` passes and the reason shows in the job log.
- The cooldown job fails closed when `npm view` cannot be reached.
