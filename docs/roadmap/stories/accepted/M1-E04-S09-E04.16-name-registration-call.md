# E04.16 Name registration call

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 9  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** owner, protocol  
**Readiness:** ready · **Sheet title:** Claim a name

## Description

Register a human-readable name for the account on chain, with the user's passkey approving it and the sponsor paying.

Blocked from outside, not for sprint one. The name service cannot finish its move to the current ledger until compact#875 merges (in review, idle when last checked).

In scope: A design note first: how the account owns a name. The account contract has no name circuit, so "a call on the account, signed with an owner key" (the board text) does not exist yet. Two routes: the name service authenticates through the account contract, or an interim where the name is held by a commitment to the device key. `owner.claimName(name)`: availability check, the registration call, follow until final. Name rules (length, characters, reserved names) as shared constants in `protocol`. Typed results: taken, invalid, not allowed by the sponsor policy.

Out of scope: resolving a name, which is E04.18 (name resolution). Screens, which are E08.01 (name claim screen). Subdomains for child Passports, which are E10.08 (child Passport subdomain).

## Dependencies

**Blocked by:** E04.12 Account deploy in waves: plan, send, resume, activate. External: compact#875; the choice between the two name service contract versions; the `passport.night` name itself.  
**Unlocks:** E04.18 Name-to-ACC resolution; E08.01 Name claim screen

## Acceptance criteria

- The design note is merged and says which name format V1 uses (the docs say `alice.passport.night`, the stories say `maya.night`).
- On Preview, an account registers a name with one passkey prompt, and the user's wallet pays nothing.
- A taken name gives the typed "taken" result before any prompt.
- A second account cannot take a registered name (test on a local node).
- The fee for a registration is recorded in the test output and is within the sponsor's cap.
