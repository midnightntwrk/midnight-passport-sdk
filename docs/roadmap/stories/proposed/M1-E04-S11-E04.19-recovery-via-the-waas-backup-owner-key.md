# E04.19 Recovery via the WaaS backup owner key

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 11  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** owner, adapter-waas  
**Readiness:** to discuss implementation · **Sheet title:** Recover with the WaaS key

> **To discuss before implementing:** Decide whether the WaaS key adds the new owner key directly (fast, no recovery circuits) or goes through the timelocked recovery with cancel and alarms, which needs the recovery circuits from Guardian recovery. The quick win assumes the direct add.

## Description

Recover using the optional WaaS backup owner key instead of guardians.

A quick recovery path before guardians exist: on a new device, the WaaS backup owner key signs the add of the new passkey's owner key (rule 12). Guardian recovery comes later, with its own delay and alarms.

Accounts are now born with the p256 arm only, so the WaaS key can sign only after the k256 arm is installed and the key is enrolled, in E04.22 (add circuits to a live account) and E04.17 (WaaS backup owner key). The new device's passkey joins on the p256 arm.

## Dependencies

**Blocked by:** E04.17 WaaS key as isolated backup owner key; E04.22 Add circuits to a live account: grant-spend circuits and later arms  
**Unlocks:** no other story.

## Acceptance criteria

- On a fresh device, the WaaS backup owner key adds the new passkey's owner key, and the user is back in the same account.
- The direct-add versus timelocked-recovery decision is recorded.
