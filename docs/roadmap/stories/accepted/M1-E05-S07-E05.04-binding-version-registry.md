# E05.04 Binding version registry

**Epic:** E05 · Contract binding · **Milestone:** 1 Foundation · **Step:** 7  
**Epic issue:** [#48](https://github.com/midnightntwrk/midnight-passport-sdk/issues/48)  
**Packages:** contract  
**Readiness:** ready · **Sheet title:** Version registry

## Description

Given a deployed account, tell which build of the account contract (ACC) it is and return the binding that can talk to it. An account from an unknown build gets a typed error, never a best-effort call (rule 5, the version axes). The first beta will already have two builds in its life if any contract fix lands after accounts exist, so this is not a later nicety.

In scope: A table from binding version to manifest, kept in `contract`. One row at first. Identification: read the verifier keys an account has on chain and match their hashes against each known manifest. The result: binding version, which arms are present, and whether the build is current, old but supported, or unsupported. The typed "unknown version" error. The binding column of `docs/compatibility.md`, generated from the table.

Out of scope: the version type itself, which is E03.05 (version axes). Migrating an account from one build to another: there is no such operation; a new build means a new account.

## Dependencies

**Blocked by:** E05.03 ACC artifact loader (module, decoder, manifest); E03.05 Wire and binding version axes; E04.06 Indexer seam: transaction status and account state. E04.06 gives the on-chain read.  
**Unlocks:** nothing on the board. E04.13 (existing-account lookup) uses it to try each supported version.

## Acceptance criteria

- An account deployed from the pinned build on a local node is identified with the right version and arms.
- An account whose verifier keys match no manifest gives the typed "unknown version" error, and no call is built.
- A fixture with two manifests identifies accounts of each.
- A one-arm account is identified from the keys it has; missing arms do not make it "unknown".
- `docs/compatibility.md` is regenerated from the table in CI, and a stale file fails the check.
