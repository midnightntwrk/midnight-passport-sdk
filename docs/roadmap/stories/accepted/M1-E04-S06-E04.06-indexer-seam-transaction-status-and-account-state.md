# E04.06 Indexer seam: transaction status and account state

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 6  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** adapter-indexer (proposed), core  
**Readiness:** ready · **Sheet title:** Status via the indexer

## Description

Read transaction status and account contract (ACC) state through one seam, so the SDK does not depend on one hosted indexer. The interface is defined in E03.03 (seam interfaces); this story is the first implementation.

The architecture doc has no indexer seam and no package for it, although three board stories assume one. This story proposes the package `adapter-indexer`.

In scope: Reads: contract state at an address, whether a contract exists at an address, status of a transaction, the stream of state changes for one account. Two sources behind the seam: the indexer's API, and the node's own state query for cases where the indexer lags behind a block. Bounded polling and reconnect for subscriptions. Typed results: "not found" is different from "indexer unreachable". A recorded-response test suite and one Preview test.

Out of scope: reading grants, which is E10.04 (on-chain grant reads). The coin store and inbox, which are E07.01 (coin store). Reading private data with a viewing key.

## Acceptance criteria

- A deploy and a call are followed from submit to final through the seam only.
- With the indexer stopped, a read gives the typed "unreachable" error and never "not found" (test).
- A state read right after a block is served from the node source when the indexer has not caught up (test with a delayed indexer stub).
- No code outside `adapter-indexer` imports an indexer client or builds an indexer query.
- The adapter passes the indexer contract test from E03.03 (seam interfaces) and the same test passes on the in-memory stub.
