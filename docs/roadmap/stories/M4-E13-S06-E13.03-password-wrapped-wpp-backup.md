# E13.03 Password-wrapped WPP backup

**Epic:** E13 · Private data and backup · **Milestone:** 4 Private data and sync · **Step:** 6  
**Epic issue:** [#56](https://github.com/midnightntwrk/midnight-passport-sdk/issues/56)  
**Packages:** owner, core  
**Readiness:** to discuss implementation · **Sheet title:** Encrypted backup

> **To discuss before implementing:** How should the backup be encrypted: a password with a KDF, the passkey PRF, or the recovery secret? A passkey-only wrap is lost with the last device, which is exactly when a backup is needed. Guardian recovery already restores the WPP account key through the recovery secret, so is a separate password needed at all? See requirements open question 1.

## Description

Back up the private state, encrypted with a password only the user knows.

The WPP account key stays in the owner kernel and is wrapped for backup. The backup never leaves the device in plaintext.
