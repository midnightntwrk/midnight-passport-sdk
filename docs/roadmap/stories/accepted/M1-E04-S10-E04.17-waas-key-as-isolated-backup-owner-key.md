# E04.17 WaaS key as isolated backup owner key

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 10  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** owner, adapter-waas  
**Readiness:** ready · **Sheet title:** WaaS backup owner key

## Description

A user can add a backup owner key held by a wallet-as-a-service provider, only when the provider isolates that key to the Passport app (rule 12, the WaaS key only as an isolated backup). It is never the main key and is never used from a dApp.

The board text says the key is "enrolled at deploy as a second owner key on the k256 arm". Accounts are now born with the p256 arm only, so the k256 arm has to be installed first. Enrolling becomes a step after birth.

Not for sprint one. It waits on E04.07 (WaaS adapter) and on E04.22 (add circuits to a live account).

In scope: The flow: check the provider's isolation, install the k256 arm if the account lacks it, enrol the provider's key as a second owner key (the passkey approves), write the account metadata. The isolation check as a typed precondition, with the rule for what counts as isolated. The metadata written at enrolment: account address, binding version, key versions. No secret in readable form. A read: does this account have a backup key, and is its metadata current.

Out of scope: recovering with the key, which is E04.19 (recovery via the WaaS backup owner key). k256 keys from the user's own wallet, which is E19.03 (k256 wallet as an owner key).

## Dependencies

**Blocked by:** E04.07 adapter-waas: k256 key and account metadata; E04.12 Account deploy in waves: plan, send, resume, activate; E04.22 Add circuits to a live account: grant-spend circuits and later arms  
**Unlocks:** E04.19 Recovery via the WaaS backup owner key

## Acceptance criteria

- On a local node, a p256-arm account ends with a k256 backup owner key that makes one owner call, using the fake provider from E04.07 (WaaS adapter).
- Enrolment is refused with a typed error when the provider does not report isolation.
- The enrolled key uses k256 envelope 0. A test proves envelope 1 cannot be selected.
- The metadata is read back after the write and matches; a mismatch gives a typed error.
- The number of passkey prompts for the whole flow is counted and documented.
