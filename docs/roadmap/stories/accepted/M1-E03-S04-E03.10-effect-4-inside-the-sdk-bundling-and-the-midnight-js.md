# E03.10 Effect 4 inside the SDK: bundling and the midnight-js adapter file

**Epic:** E03 · Workspace, seams, and guardrails · **Milestone:** 1 Foundation · **Step:** 4  
**Epic issue:** [#46](https://github.com/midnightntwrk/midnight-passport-sdk/issues/46)  
**Packages:** core, repo CI, docs/adr/  
**Readiness:** ready · **Sheet title:** none (new story)

## Description

The SDK is written with Effect 4, bundled inside its own build. midnight-js 5.0.0, compact-js and the wallet SDK use Effect 3, and values of one major cannot be run by the other. This story adds the one file where the two meet, the packaging that keeps Effect 4 out of the app's dependency tree, and the CI guard that keeps Effect out of the public types.

Proposed by the provider. This story is not on the board. It was split out of E03.03 (seam interfaces) so the decision is built and tested before any seam signature is written.

In scope: An ADR: Effect 4 inside, bundled, exact pin; one adapter file for Effect 3; public API is Promises and plain types. The adapter file in `core`: `fromV3` (runs an Effect 3 effect and rebuilds its exit as Effect 4) and `fromPromise` (wraps midnight-js Promise APIs). It carries success, typed errors, defects and interruption. Packaging: Effect 4 bundled into the dist of `core`, not listed in `dependencies`. A CI guard on `dist/*.d.ts`: no `effect`, rxjs, midnight-js or wallet-sdk type, and no TS2883. The public shapes: SDK error classes with `_tag` and `code`; observable reads as `subscribe(listener) => unsubscribe` with `current()`. A consumer smoke test: install the packed tarballs with npm, pnpm and bun next to midnight-js 5.0.0.

Out of scope: an `/effect` subpath export (waits until midnight-js moves to Effect 4). Carrying Effect services, layers or tracing across the adapter.

## Acceptance criteria

- The ADR is merged.
- The adapter file passes 8 cases: success, typed error caught by tag, defect, interruption that runs the Effect 3 finalizers, and the Promise wrapper for each.
- A lint rule fails any import of Effect 3 or of a midnight-js Effect type outside the adapter file.
- `core`'s `package.json` has no `effect` entry in `dependencies` or `peerDependencies`.
- The `.d.ts` guard fails on a fixture that exports an Effect type.
- The consumer smoke installs and imports the tarballs on npm, pnpm and bun, with one copy of Effect 3 in the tree.
