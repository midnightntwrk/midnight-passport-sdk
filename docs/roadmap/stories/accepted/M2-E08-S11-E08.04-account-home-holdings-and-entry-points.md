# E08.04 Account home: holdings and entry points

**Epic:** E08 · Passport app: the account · **Milestone:** 2 Account management and core actions · **Step:** 11  
**Epic issue:** [#51](https://github.com/midnightntwrk/midnight-passport-sdk/issues/51)  
**Packages:** The Passport app. From the SDK: core  
**Readiness:** ready · **Sheet title:** none (new story)

## Description

The screen a user lands on after onboarding and on every later visit. E06.02 (deploy progress UI) ends on "account ready" and E06.03 (returning-user resume) routes "to the account", and both leave the screen itself to this epic. No board story builds it.

Proposed by the provider. This story is not on the board.

Cannot start yet. It needs the component library from E02.02 (UI components) and a repository for the Passport app. Neither exists.

In scope: Holdings per asset from E07.05 (holdings and activity reads), with amounts still being checked shown apart, updating without a reload. Entry points: send (E08.03 (send screens)), receive (E08.05 (receive screen and deposit page)), activity (E08.02 (activity feed)) and the name screen (E08.01 (name claim screen)). Grants, devices and backup get their entries when their epics build them. Payments in progress, from the pending payments read of E07.03 (send to a wallet address). A row opens the send screens; this screen has no flow of its own. States: no funds yet, indexer unreachable (last values marked stale). Showing the account's name waits on a lookup from account to name, which E04.18 (name resolution) has only if the name service supports it. Until then the screen shows the name only on the device that claimed it.

Out of scope: Navigation patterns and the app shell, which are decided in E02.02. Routing a returning user, which is E06.03. The starting balance, which is E04.09 (starting balance).

## Dependencies

**Blocked by:** E07.05 Holdings and activity reads; E06.02 Deploy progress and balance UI; E06.03 Returning-user account resume; E02.02 UI component library and interaction patterns. External: a repository for the Passport app.  
**Unlocks:** nothing on the board. E08.01 (name claim screen), E08.02 (activity feed), E08.03 (send screens) and E08.05 (receive screen and deposit page) get an entry point here but can each be built without it.

## Acceptance criteria

- UI tests with fixture holdings cover every state. They run before E07.05 (holdings and activity reads) exists.
- Once E07.05 exists: on a local node a new account lands here after onboarding and shows the no-funds state. After a deposit from another wallet, made through the builder of E07.01 (inbox, coin store and deposits), the amount appears with no reload.
- Each entry point opens its screen, or is hidden while that screen does not exist.
- The screen never prints the account's contract address as something to pay to.
