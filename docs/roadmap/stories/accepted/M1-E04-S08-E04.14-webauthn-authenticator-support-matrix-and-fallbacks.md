# E04.14 WebAuthn authenticator support matrix and fallbacks

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 8  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** adapter-browser, docs/  
**Readiness:** ready · **Sheet title:** Authenticator support

## Description

A tested list of which browsers and authenticators can own a Passport account, and what the user sees when theirs cannot. The account contract accepts one fixed shape of WebAuthn response. Whether each real authenticator and browser produces that shape is not known.

Board title: WebAuthn PRF support matrix and fallbacks. PRF is dropped, so the matrix now tests what the p256 arm needs.

Needs hardware. Real phones, laptops and security keys. Tests have run on one real authenticator so far, a synced platform passkey in Chrome on Linux; everything else ran on Chromium's virtual one.

In scope: A test page built on E04.11 (passkey as the first owner key) that records, per device: ES256 support, discoverable credentials, the length and field order of the client data, the authenticator data length and flags, and the rate of responses outside the accepted profile. Runs on: iCloud Keychain (Safari on iOS and macOS), Google Password Manager (Chrome on Android), Windows Hello, one hardware security key, Firefox on desktop. Synced passkeys: the same credential on two devices is one owner key to the contract. Check that the second device can sign. Capability detection before any deploy, and a message for unsupported devices. The published list in `docs/`.

Out of scope: changing the contract to accept more shapes. That is a contract decision; this story gives it the data.

## Dependencies

**Blocked by:** E04.11 Passkey on the p256 arm as the first owner key. The on-chain rows also need E04.12 (wave deploy).  
**Unlocks:** E06.01 Onboarding flow: passkey creation. That story takes its unsupported-device message from this list.

## Acceptance criteria

- The list has a row for each platform above with: works, works with re-prompts (and the rate), or does not work (and why).
- At least one phone and one laptop complete create, activation and one owner call against a node.
- An unsupported authenticator gets the typed "unsupported" result before any transaction is sent.
- The synced-passkey row says what was tested and on which two devices.
- The raw recordings are checked in, so the list can be re-derived.
