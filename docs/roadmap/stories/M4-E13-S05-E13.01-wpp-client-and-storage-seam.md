# E13.01 WPP client and storage seam

**Epic:** E13 · Private data and backup · **Milestone:** 4 Private data and sync · **Step:** 5  
**Epic issue:** [#56](https://github.com/midnightntwrk/midnight-passport-sdk/issues/56)  
**Packages:** core, adapter-wpp-drive  
**Readiness:** ready · **Sheet title:** Storage adapter

## Description

Encrypted local storage for the account's private state.

The WPP client in core holds the package format, encryption, and entry integrity checks. Storage backends are adapter-wpp-<backend> packages that see ciphertext only.

## Dependencies

**Blocked by:** E03.03 Seam interface definitions; E03.04 Owner kernel secret boundary  
**Unlocks:** E13.03 Password-wrapped WPP backup; E13.04 adapter-wpp-<backend> targets (Drive first); E13.05 core: WPP PrivateStateProvider (one package key); E13.08 Client read surface and package-key handoff; E14.06 Private-state sync over WPP

## Acceptance criteria

- The WPP client in core writes and reads packages, with only ciphertext reaching storage.
- Entry integrity checks reject tampered entries.
