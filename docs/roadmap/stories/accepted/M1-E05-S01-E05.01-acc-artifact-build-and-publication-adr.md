# E05.01 ACC artifact build and publication (ADR)

**Epic:** E05 · Contract binding · **Milestone:** 1 Foundation · **Step:** 1  
**Epic issue:** [#48](https://github.com/midnightntwrk/midnight-passport-sdk/issues/48)  
**Packages:** contract, docs/adr/  
**Readiness:** ready · **Sheet title:** Artifact ownership and publication

## Description

Record who builds and publishes the account contract (ACC) artifact, where it lives and how it is versioned, and agree the first build the SDK pins. The "who" is answered: the contract stays in the passport repo, built by the provider and the contract owner. What is still missing is an artifact anyone can download, and a list of the contract decisions that must be closed before the pin, because each of them changes every account address.

In scope: the ADR, with the repository, the publishing channel, the version scheme, and how a new build reaches E05.04 (binding version registry). What an artifact contains: compiled module, ledger decoder, verifier keys, ZKIR, and a manifest with hashes, the compiler version, the zkir version and the wave-1 circuit list per arm. Where the proving keys go (about 12 GB for all circuits): to the prover, not to clients. An interim until upstream publishes: CI builds a pinned commit of the passport repo and the manifest hashes are committed in the SDK.

Also in scope: a pin checklist for the first build, agreed with the contract owner. It has five items. The build is compiled with Compact 0.36, which Preview requires. The open contract changes that alter verifier keys have landed, things like selective device revocation ([passport#198](https://github.com/midnightntwrk/passport/pull/198)). The WebAuthn origin length is the one of the beta origin, because it is fixed at compile time. The wave-1 circuit list for the p256 arm is final, because it is part of the address. Every constructor input is reproducible, for the same reason.

Out of scope: changing the contract. Loading the artifact, which is E05.03 (ACC artifact loader).

## Dependencies

**Blocked by:** nothing. Nothing in the SDK. It needs the contract owner and the contract-side PR that removes PRF for user devices.  
**Unlocks:** E05.02 ACC circuit interface for dApp composition; E05.03 ACC artifact loader (module, decoder, manifest); E04.11 Passkey on the p256 arm as the first owner key. For E04.11, the origin length.

## Acceptance criteria

- The ADR is merged, with the contract owner as reviewer.
- Each checklist row is closed or carries a recorded decision to defer it, with the cost stated.
- One artifact exists at a stable URL or package name, with its manifest, built from a named commit.
- Two builds of that commit give the same verifier-key hashes.
- The proving keys of that build are loaded on the prover the SDK tests use.
