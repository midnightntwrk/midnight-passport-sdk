# E03.08 Domain-separation tag constants

**Epic:** E03 · Workspace, seams, and guardrails · **Milestone:** 1 Foundation · **Step:** 4  
**Epic issue:** [#46](https://github.com/midnightntwrk/midnight-passport-sdk/issues/46)  
**Packages:** protocol  
**Readiness:** ready · **Sheet title:** Domain-separation tags

## Description

One set of tag constants in `protocol` for every hash and signature that the SDK itself defines, so a signature made for one purpose cannot be reused for another.

The scope is narrower than the board text. The digests that each signing arm of the account contract (ACC) checks are fixed by the contract. The SDK cannot choose them, so they are binding data in `contract`, not tags in `protocol`. And with P-256 device keys there is no passkey-derived key, so no key-derivation tags for it.

In scope: A naming scheme: `midnight:passport:<area>:<purpose>:v<n>`. Tags for the messages the SDK defines: the grant request, the possession proof, the sign-in message, and the four recovery tags the docs already name. A registry file that lists every tag with its purpose, and a uniqueness test. Tags for any key derivation that E04.20 (account secrets without a passkey-derived secret) ends up specifying.

Out of scope: the arm digests (k256, p256 WebAuthn, JubJub), which E04.02 (key providers) builds from the contract binding. The message formats, which are E09 (scoped grants foundation) and E21 (guardian recovery).

## Dependencies

**Blocked by:** E03.02 Monorepo scaffold for mn-passport-* packages  
**Unlocks:** E04.02 KeyProvider across p256, k256 and JubJub; E09.01 GrantRequest: browser profile; E09.02 GrantRequest: agent profile; E09.03 Sign-in message (MIP §10); E19.01 Device enrollment request (QR or link payload); E21.01 MIP-0022 recovery message types

## Acceptance criteria

- Every tag is exported from one module in `protocol` and follows the naming scheme.
- A test fails if two tags are equal or if one is a prefix of another.
- A lint or test fails if a string starting with `midnight:passport:` appears outside that module.
- The registry file lists each tag, its purpose and the story that uses it.
