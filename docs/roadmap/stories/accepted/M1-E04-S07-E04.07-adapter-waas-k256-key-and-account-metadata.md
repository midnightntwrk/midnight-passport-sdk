# E04.07 adapter-waas: k256 key and account metadata

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 7  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** adapter-waas, core  
**Readiness:** ready · **Sheet title:** WaaS adapter and metadata

## Description

An adapter for a wallet-as-a-service provider. It gives the SDK a k256 key that can become a backup owner key, and a place to keep public account metadata. The metadata never holds a viewing key or any secret in readable form (rule 12, the WaaS key only as an isolated backup).

Not for sprint one. It waits on a spike: a real key from the WaaS provider has not been shown signing an account contract call.

In scope: A spike first: the provider's raw-message signing produces a signature that the account contract's k256 arm (envelope 0) accepts on a local node. The key provider side: `publicKey()` and `sign(challenge)` over the provider's SDK. The Account metadata seam: namespaced, versioned entries; each write is read, merge, write, read back. Entries fit in 2 KB. A fake provider for tests.

Out of scope: enrolling the key on an account, which is E04.17 (WaaS backup owner key). Recovery with it, which is E04.19 (recovery via the WaaS backup owner key). Choosing the provider.

## Dependencies

**Blocked by:** E03.03 Seam interface definitions; E04.02 KeyProvider across p256, k256 and JubJub. A spike with a real provider key comes first.  
**Unlocks:** E04.17 WaaS key as isolated backup owner key

## Acceptance criteria

- The spike result is written down: one owner call signed by a real provider key, accepted on a local node, or the reason it cannot work.
- The adapter passes the key provider and metadata contract tests from E03.03 (seam interfaces) against the fake provider.
- Two writers that race on one metadata entry end with both changes or a typed conflict, never a silent loss (test).
- An entry above the size limit is refused before any network call.
- A test scans every metadata write for the bytes of the test secrets and finds none.
