# E03.02 Monorepo scaffold for mn-passport-* packages

**Epic:** E03 · Workspace, seams, and guardrails · **Milestone:** 1 Foundation · **Step:** 3  
**Epic issue:** [#46](https://github.com/midnightntwrk/midnight-passport-sdk/issues/46)  
**Packages:** All twelve listed above, plus repo config  
**Readiness:** ready · **Sheet title:** Package skeleton

## Description

Create the workspace packages so every later story has a place to put code: the six libraries, plus the adapter packages that E04 (account deployment) fills in. Each package builds and tests on its own. No feature code.

In scope: Six libraries under `@midnight-ntwrk/mn-passport-*`: `owner`, `connect`, `agent`, `core`, `contract`, `protocol`. Empty adapter packages that E04 (account deployment) needs: `adapter-prover-remote`, `adapter-broadcast`, `adapter-browser`, `adapter-nodejs`. Two more empty packages: `adapter-indexer` (proposed, see E04.06 (indexer adapter)) and a private `dev` package for the local stubs of E03.03 (seam interfaces). `scripts/dependency-graph.mjs` gains the packages it lacks: those two and `adapter-registry`. Shared build, test and lint config; TypeScript project references that follow the graph. A split build with `sideEffects: false` and one `exports` map per package.

Out of scope: Publishing a pre-release. It needs npm org access, so it moves to E03.07 (signed npm release). Effect bundling and the adapter file, which are E03.10 (Effect 4 inside the SDK). `adapter-waas`, scaffolded with E04.07 (WaaS adapter). The Passport app, which lives in another repo.

## Acceptance criteria

- `pnpm install --frozen-lockfile`, `build`, `test`, `lint` and `format:check` pass from a clean checkout.
- Each of the twelve packages builds alone (`pnpm --filter <pkg> build`) and has one passing placeholder test.
- `tests/dependency-rules.test.mjs` passes with the real manifests and project references.
- `adapter-registry`, `adapter-indexer` and `dev` are in the dependency graph, with their allowed imports.
- No package declares a dependency outside the pin table in `docs/compatibility.md`.
