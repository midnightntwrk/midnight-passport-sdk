## Description

One timeline of what happened on the account: its creation, payments in and out, and later grants and device changes. The board has the app build it "from the indexer seam and the inbox". The decoding is now in E07.05 (holdings and activity reads); this story is the screen.

Board title: Activity feed (indexer and inbox). Rewritten as a screen only. Decoding the chain moved to the new SDK story E07.05.

Cannot start yet. It needs the component library from E02.02 (UI components) and a repository for the Passport app. Neither exists.

In scope: A list grouped by day, one row per record of E07.05, with a detail view that shows the transaction id. Rows in progress come from the same read, which carries the pending payments of E07.03 (send to a wallet address). They turn into confirmed or failed rows. Rows with "amount unknown", for sends made on another device. An empty state, a stale marker when the indexer cannot be reached, and loading more on scroll. The row rules say when a row happened, which day it sits under, and what survives a reload.

Out of scope: Decoding, which is E07.05. The grant list, which is E12.04 (grant list and revoke screen). Device screens, which are E20 (Passport app: backup and devices).

## Dependencies

**Blocked by:** E07.05 Holdings and activity reads; E04.06 Indexer seam: transaction status and account state; E02.02 UI component library and interaction patterns. E04.06 (indexer seam) is reached through E07.05 (holdings and activity reads); the screen does not call the indexer. External: a repository for the Passport app.  
**Unlocks:** nothing on the board.

## Acceptance criteria

- UI tests with fixture records cover every row kind and state. They run before E07.05 (holdings and activity reads) exists.
- Once E07.05 exists: on a local node two deposits appear in order, and are still there after a reload.
- With a fixture of a failed send, the row shows as failed. It does not disappear.
