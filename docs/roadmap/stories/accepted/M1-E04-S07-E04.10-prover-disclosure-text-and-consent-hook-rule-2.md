# E04.10 Prover disclosure text and consent hook (rule 2)

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 7  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** owner, core  
**Readiness:** ready · **Sheet title:** Prover disclosure

## Description

The user is told that the V1 prover sees the private inputs of each proof (rule 2, prover disclosure), and the app can record that they accepted. With P-256 device keys every owner call is proved remotely, so there is no flow in which this does not apply.

In scope: The disclosure text as a constant in `owner`, versioned, with a short and a long form. A consent hook: the app passes a function that the SDK calls before the first proof request of an account; proving does not start until it resolves to "accepted". The accepted text version is kept in the local account record, so the user is asked again only when the text changes. The same hook exposed for `connect` and `agent`, where a dApp's own circuits are proved.

Out of scope: the screens and final copy, which are E06 (Passport app: onboarding) and E02.01 (app design). Encrypting inputs to a trusted-hardware prover, which becomes mandatory only once such a prover exists.

## Acceptance criteria

- With no consent recorded, a proof request does not leave the client (test with a network recorder).
- Declining gives a typed error and sends nothing.
- After acceptance the hook is not called again for the same text version; changing the version calls it again.
- The text names what the prover sees for an account call and for a dApp call, and who runs the prover.
- The text is reviewed by the product owners before merge.
