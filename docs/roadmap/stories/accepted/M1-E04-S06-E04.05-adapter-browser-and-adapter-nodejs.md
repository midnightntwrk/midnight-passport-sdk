# E04.05 adapter-browser and adapter-nodejs

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 6  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** adapter-browser, adapter-nodejs  
**Readiness:** ready · **Sheet title:** Platform adapters

## Description

The same SDK code runs in a browser page and in Node.js. Each adapter implements the Platform seam: network access, loading the WASM runtimes in the right order, local persistence, randomness, and WebAuthn or its absence.

The board text says the browser adapter "wraps passkeys with PRF". PRF is dropped. The adapter exposes plain WebAuthn create and get; the passkey rules live in E04.11 (passkey as the first owner key).

In scope: `adapter-browser`: a WASM boot step that works with Vite and esbuild; no Node built-ins in the bundle; plain `navigator.credentials` create and get; local persistence; a way to list and wipe everything the SDK stored. `adapter-nodejs`: the same seam for backends, agents and tests. WebAuthn is reported as unavailable. A smoke test on both: load the runtimes, read one contract state, build one unproven call. A bundle size report in CI.

Out of scope: passkey profile checks and re-prompts, which are E04.11 (passkey as the first owner key). Encrypted storage, which is E17 (private data and backup). React Native or other runtimes.

## Acceptance criteria

- A Vite app and an esbuild app that import `owner` with `adapter-browser` build and run the smoke test in headless Chromium.
- The browser bundle imports no `node:` module; a build-time check fails if one appears.
- The smoke test passes in Node.js with `adapter-nodejs`.
- CI prints the gzip size of JS and WASM for the browser build and fails on a growth above a set threshold.
- The wipe function leaves IndexedDB, localStorage and sessionStorage with no SDK entry (test).
- Both adapters pass the Platform contract test from E03.03 (seam interfaces).
