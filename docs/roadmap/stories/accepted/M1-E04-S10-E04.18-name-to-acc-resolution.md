# E04.18 Name-to-ACC resolution

**Epic:** E04 · Account deployment · **Milestone:** 1 Foundation · **Step:** 10  
**Epic issue:** [#47](https://github.com/midnightntwrk/midnight-passport-sdk/issues/47)  
**Packages:** core  
**Readiness:** ready · **Sheet title:** Name resolution

## Description

Turn a name into the account it belongs to, so people and dApps use a name instead of an address. Payment then goes through a deposit call (rule 3, pay through deposit calls); the raw account address is never shown as a payment address.

Blocked from outside, not for sprint one. Same blocker as E04.16 (name registration): the name service's move to the current ledger.

In scope: `core.resolveName(name)`: returns the account address and the binding version, or a typed "not registered". An availability check for onboarding, built on the same read. Reverse lookup (account to name) if the name service supports it. A short cache with a stated lifetime.

Out of scope: registration, which is E04.16 (name registration). Paying a name, which is E07.02 (transfers via deposit calls). Sign-in by name, which is E13.02 (connect: sign-in verification).

## Dependencies

**Blocked by:** E04.16 Name registration call; E04.06 Indexer seam: transaction status and account state  
**Unlocks:** E07.02 Pay another Passport: shielded, in one joined transaction; E13.02 connect: sign-in verification. Also the name option of E04.13 (existing-account lookup).

## Acceptance criteria

- A registered name resolves to its account on Preview.
- An unregistered name returns the typed "not registered" result, not an exception.
- With the indexer unreachable the call fails with the typed "unreachable" error; it never returns "not registered" (test).
- The resolved address is checked to be an account contract of a known binding version before it is returned.
- `connect` and `agent` can call it without importing `owner`.
