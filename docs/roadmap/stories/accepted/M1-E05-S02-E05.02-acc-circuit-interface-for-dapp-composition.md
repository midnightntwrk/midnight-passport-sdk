# E05.02 ACC circuit interface for dApp composition

**Epic:** E05 · Contract binding · **Milestone:** 1 Foundation · **Step:** 2  
**Epic issue:** [#48](https://github.com/midnightntwrk/midnight-passport-sdk/issues/48)  
**Packages:** contract  
**Readiness:** ready · **Sheet title:** Contract interface for dApp circuits

## Description

Publish the account contract's (ACC) interface so a dApp contract can call it from its own circuits, for example to authenticate the user or to take a payment and run its own logic in one transaction. The interface ships with the artifact and carries the same binding version.

Not for sprint one. Nothing in Foundation uses it. The first user is E15.01 (intent joiner: dApp intent plus account payment).

In scope: The interface file a dApp's Compact code imports, generated from the pinned build, as part of the artifact from E05.01 (ACC artifact publication). A sample dApp contract in the repo's test fixtures that calls one account circuit. A check in CI that the sample compiles against the pinned interface. A doc page: which account circuits a dApp may call, and what the user has to approve for each.

Out of scope: building and joining the transaction for such a call, which is E15.01 (intent joiner). Any change to the account contract.

## Dependencies

**Blocked by:** E05.01 ACC artifact build and publication (ADR)  
**Unlocks:** nothing on the board. E15.01 (intent joiner) needs it in practice.

## Acceptance criteria

- The artifact contains the interface file, and the manifest lists its hash.
- The sample dApp contract compiles against it in CI with the pinned compiler.
- On a local node, the sample contract's call into an account succeeds with a valid approval and fails without one.
- The interface's binding version equals the artifact's; a test fails if they differ.
- The doc page lists the callable circuits.
