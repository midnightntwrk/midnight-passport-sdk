## Description

Publish the packages to npm under `@midnight-ntwrk/` with provenance, from CI, in a way that can be reproduced from a clean checkout. This story also takes the "publish a pre-release" criterion that the board had on E03.02 (monorepo scaffold).

Blocked from outside: it needs publish rights on the `@midnight-ntwrk` npm org. Until then only the dry run can be built.

In scope: A release workflow that a maintainer starts by hand. Nothing publishes on its own. npm provenance; a signed tag; a changelog entry per package. A reproducibility check: two clean builds of the same commit give the same tarball hashes. A dry-run mode that packs every package and runs the consumer smoke from E03.10 (Effect 4 inside the SDK) on the tarballs. One pre-release of the six libraries once access exists.

Out of scope: commit signing and DCO, which are contributor rules in `CONTRIBUTING.md`, not pipeline work. Publishing the account contract artifact, which is E05.01 (ACC artifact publication).

## Dependencies

**Blocked by:** E03.02 Monorepo scaffold for mn-passport-* packages; E03.01 Exact pins, 7-day cooldown, lockfile: the remaining work. External: publish rights on the npm org, with provenance.  
**Unlocks:** nothing on the board. Partners need it before they can install the SDK without a git checkout.

## Acceptance criteria

- The dry run packs all packages in CI and the tarball hashes match across two runs.
- The workflow cannot start from a push or a PR; only from a manual trigger by a maintainer.
- A pre-release of each library is on npm with a provenance attestation that points at the commit. *(needs npm access)*
- Installing the pre-release in an empty project and importing each package works on npm, pnpm and bun. *(needs npm access)*
