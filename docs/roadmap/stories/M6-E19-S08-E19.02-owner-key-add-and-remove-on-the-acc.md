# E19.02 Owner key add and remove on the ACC

**Epic:** E19 · Devices and multi-device sync · **Milestone:** 6 Private data and sync · **Step:** 8  
**Epic issue:** [#57](https://github.com/midnightntwrk/midnight-passport-sdk/issues/57)  
**Packages:** owner  
**Readiness:** to discuss implementation · **Sheet title:** Add and remove devices

> **To discuss before implementing:** Architecture change: a new device is expected to use the synced passkey from the passkey provider, so the same passkey, and the same owner key, works on all of the user's devices. That contradicts "each device gets its own key". Decide whether adding a device needs any ACC call at all, or only the new-device bootstrap, while keeping the door open for one owner key per device (device-bound passkeys, wallets, or users who want per-device revocation).

## Description

Each device gets its own key; the owner can add a device, remove one, or switch off a lost one.

One key per device: each new device adds its own owner key to the ACC, approved with a tap on an existing device. Removing a lost device revokes its key on chain.

**Blocked by:** E04.12 Multi-wave ACC deploy planner; E19.01 Device enrollment request (QR or link payload)

## Acceptance criteria

- An owner key is added and removed on the ACC, approved from an existing device.
- The synced-passkey decision is recorded.
