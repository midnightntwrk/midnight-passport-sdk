# E06.02 Deploy progress and balance UI

**Epic:** E06 · Passport app: onboarding · **Milestone:** 1 Foundation · **Step:** 10  
**Epic issue:** [#49](https://github.com/midnightntwrk/midnight-passport-sdk/issues/49)  
**Packages:** The Passport app. From the SDK: owner  
**Readiness:** ready · **Sheet title:** Deploy progress and balance

## Description

Show the user what is happening while the account is created, recover on screen when a step fails, and end on a ready account. With the p256-only start the deploy is short (2 transactions in tests, on a one-arm account), so the wait is mostly the activation proof and the chain, not a long row of waves.

Board title: Deploy-wave progress and balance UI.

Cannot start yet. Same gate as E06.01 (onboarding flow): E02.02 (UI components) and an app repository.

In scope: A progress screen driven by the events of E04.12 (wave deploy): preparing, each transaction in a block, proving the activation, activated. The activation prompt, with a line that says what it approves. Failure states: sponsor busy, a refused transaction that is being retried, prover busy, network lost. Each has a retry that continues, never restarts. Closing the tab and coming back resumes at the right step. The end screen: account ready. The starting balance is shown when E04.09 (starting balance) exists, and "balance pending" until then.

Out of scope: the SDK deploy logic. The account home screen, which is E08 (Passport app: the account).

## Dependencies

**Blocked by:** E04.12 Account deploy in waves: plan, send, resume, activate; E06.01 Onboarding flow: passkey creation. The balance part also needs E04.09 (starting balance).  
**Unlocks:** nothing on the board. The board's name claim step is merged into E08.01 (name claim screen).

## Acceptance criteria

- Each SDK progress event changes the screen within one second (UI test with a stubbed SDK).
- A simulated refusal of the second transaction shows a retry state and finishes without sending the first transaction again.
- Reloading the page in the middle of a deploy continues from the last confirmed step.
- The screen never shows a wave number, a DUST amount or an error code to the user; a details view may.
- On Preview, the time from "create" to "ready" is measured in the end-to-end test and written to the test report.
- The flow ends on "account ready" whether or not a starting balance exists.
